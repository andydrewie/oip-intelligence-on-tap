navigation

Owner: lib/scenarios.mjs:panelForTarget · app/page.tsx:Home · app/ui.tsx:scrollToRoute

States: current destination; selected tab; visited panels; navigation kind: link or history; committed destination DOM; pending initial/native/history reconciliation.

Events: initial hash; native hashchange; popstate; app-link hashchange event; main-tab click; ArrowLeft; ArrowRight; Home; End; Space; pointerdown; keydown; wheel; touchstart.

  • Resolve owning panel through the shared target registry.
  • Initial non-research destination focus runs after committed layout. Research fulfills its own pending route after any filtered chapter remounts.
  • App-owned pushState links emit an app-link event and do not schedule a post-frame reconciliation.
  • Initial, native-fragment and history navigation may reconcile once in an animation frame after the browser history phase, including research destinations.
  • Cancel pending reconciliation on route change or the next pointerdown, keydown, wheel or touchstart so a new interaction owns attention.
  • Both Home applications require the current URL target to match the intent and its owner to match the selected tab, except anchors outside the tabs. Research also checks its pending target against the current URL.
  • Do not focus a missing target or one inside a hidden panel. An empty fragment returns to main.
  • Same-document interception requires the same origin, pathname and search plus a fragment. Cross-document links remain native/framework navigation.
  • React navigation anchors and the document handler preserve non-primary or modifier clicks; links targeting another browsing context are not intercepted.

What persists: The app owns same-document fragment history and preserves framework history.state when pushing or replacing entries. Scenario edits replace the current entry. Scroll restoration is manual while mounted and restored on cleanup. Visited panels retain local state; returning to an empty fragment focuses main without resetting their data.

For the reader: Main destinations focus their tab. Nested destinations open details ancestors and focus the target summary or section. Native anchors remain usable.

Browser History API with a four-tab controller. Link transitions use committed layout; only initial/native/history transitions retain one interruptible reconciliation. The browser/framework owns document navigation.

research search and chapters

Owner: app/research.tsx

States: unfiltered; matches; empty; query; pending route intent; native chapter open states.

Events: type query; clear search; new chapter destination; toggle chapter; copy chapter link.

  • Search compares title, summary and paragraph text case-insensitively.
  • A new research destination records a pending route intent; a chapter destination also clears conflicting search.
  • The next committed render fulfills the pending intent if its target still matches the current URL, then clears it. This lets filtered chapters remount before focus.
  • Typing clears pending navigation; query edits never create a route intent. Non-research destinations clear the pending research intent.
  • Only an initial/native/history transition may let Home reconcile the committed destination once; a new user intent cancels it. App-link and ordinary filter edits do not schedule this reconciliation.
  • Filtering may unmount a chapter, so native open state is not promised across removal.

What persists: Chapter destination persists; search query and chapter open states are local. Copying a chapter makes a direct chapter link rather than serializing the filter.

For the reader: Search has a label, match count and no-match help; Clear search returns focus to search. Direct entry opens/focuses the chapter summary.

Simple synchronous filter and native chapter disclosures.

share link

Owner: lib/async-state.mjs · app/ui.tsx:ShareLink

States: idle; pending; succeeded; failed; request id; immutable URL snapshot.

Events: START; RESET; SUCCEEDED; FAILED; eight-second fallback timeout.

  • Only matching request identity in pending state may complete.
  • Scope change or unmount invalidates the previous request.
  • Current hash snapshot must still match before UI completion.
  • Failed/succeeded are terminal for that request; retry creates a new identity.
  • Timeout is FAILED/manual-copy recovery, not proof that the clipboard write was cancelled.

What persists: The copied URL encodes the owning scenario or chapter. Copy status is ephemeral. The browser query is omitted from the copied URL; no private backend state is included.

For the reader: Pending copy is disabled and announced. Failure provides a selectable URL and an ordinary open link; sharing does not depend on clipboard permission.

Pure four-state request helper. Same guard applies to receipt, calculation, cost and chapter copying.
